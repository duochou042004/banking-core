## Defects found and fixed while producing this evidence

Recorded because the discovery path is part of the evidence.

1. **A malformed request body returned `500`.** A field whose JSON type did not match the contract — an amount sent as a number — escaped model binding as an unhandled exception. Reporting a client error as a server fault both misstates the fault and risks returning internal detail. Now a `400` with the stable `malformed-request` code.
2. **Concurrent migrations could collide on role creation.** Roles are cluster-scoped while the migrator's advisory lock is database-scoped, so two databases migrating on one cluster could both find a role missing and both create it, failing the second with SQLSTATE 42710. Found by running the suite repeatedly. A production deployment with more than one database on a cluster would hit the same defect. Fixed in the migration, which now catches the collision rather than checking first.
3. **A leased outbox message could not be reclaimed at the exact expiry instant**, because the predicate used a strict inequality. Fixed to `<=`.
4. **A losing concurrent command could report a rejection for a key that had a committed journal.** Found in adversarial review rather than by a test. Two commands sharing an idempotency key both reached the posting path; the winner committed, the loser's balance-policy check then correctly failed against the post-winner state, and the loser reported that rejection to its caller even though a journal for the key existed. The recovery path now re-reads the committed receipt and returns its outcome.

## What this evidence does not show

Stated plainly so nothing here is read as more than it is.

- **No independent review.** Two qualified approvals are required and none exists.
- **No durability evidence.** The test PostgreSQL runs with `fsync`, `synchronous_commit`, and `full_page_writes` off for throughput. **No backup, restore, point-in-time recovery, or crash-recovery claim may be made from this configuration.** Those exercises are outstanding Phase 1 exit requirements and need a durably configured instance.
- **No performance claim.** No benchmark methodology, workload model, or measurement exists. The known throughput limit of the gap-free per-ledger sequence is a design consequence recorded in ADR-0006, not a measured figure.
- **No supply-chain evidence.** SBOM, provenance, and release signing are outstanding.
- **No threat model for the slice** and no tailored ASVS test pass. The negative tests above are necessary, not sufficient.
- **No operator runbooks** beyond migration.
- **No permission control on backdating.** The open-period check and the audit record are in place, but any principal holding `ledger.post` may supply any effective date inside an open period. The permission itself is missing and is recorded in the task packet as Phase 2 work.
- **No compliance claim of any kind.** Nothing here is approved to hold real value or real personal data.
