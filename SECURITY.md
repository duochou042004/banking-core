# Security policy

## Project status

Banking Core is in foundation phase and has not released production software. Security reports about repository configuration, documentation that could cause an unsafe implementation, plugin/agent instructions, or future code are still welcome.

## Reporting a vulnerability

Use GitHub private vulnerability reporting for this repository when it is enabled. If that channel is unavailable, contact the repository owner through their GitHub profile and request a private reporting channel. Do not include exploit details, credentials, personal data, or customer data in a public issue.

Include the affected revision, preconditions, impact, a minimal reproduction, and any suggested mitigation. You may encrypt sensitive attachments after a maintainer provides a key.

## Response targets

These are communication targets, not guarantees:

- acknowledgment within 3 business days;
- initial severity and scope assessment within 7 business days;
- a remediation and disclosure plan based on exploitability and affected releases.

Maintainers will credit reporters who want attribution, coordinate disclosure, and request CVEs when appropriate. Safe-harbor language will be formalized before the first public release; until then, do not access data or systems you do not own or have explicit permission to test.

## Supported versions

No versions are supported yet. A version support table, patch SLA, signing keys, and security advisory process are Phase 1 release-gate requirements.
